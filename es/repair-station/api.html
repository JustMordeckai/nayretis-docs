API HTTP ​

Activa primero la API y crea un token, consulta API HTTP. Las rutas responden { "ok": true, "data": ... } y requieren Authorization: Bearer <token>.

MétodoRutaScopeConsultaDatos
GET/nay_repair/v1/historynay_repair.history.readidentifier, station (identificador), limit (de 1 a 100, 20 por defecto), before (id)items (id, identifier, stationId, station, service, price, account, time), del más reciente al más antiguo, y next: pásalo como before para la página siguiente.
GET/nay_repair/v1/statsnay_repair.stats.readdays (de 1 a 31, 7 por defecto), utcOffset (minutos, de -720 a 840, por defecto: el reloj del servidor)utcOffset usado, total, byDay (cada día listado), byStation y byService, cada uno con repairs y revenue.
GET/nay_repair/v1/stationsnay_repair.stations.readid, label, enabled, coords de cada estación.

Ejemplo:

bash
curl -H "Authorization: Bearer nay_1_xxxxxxxx" "https://api.example.com/nay_repair/v1/stats?days=7"

Respuesta:

json
{
  "ok": true,
  "data": {
    "days": 7,
    "utcOffset": 120,
    "total": { "repairs": 18, "revenue": 6150 },
    "byDay": [{ "date": "2026-10-09", "repairs": 3, "revenue": 1050 }],
    "byStation": [{ "stationId": "00000001", "station": "Hayes Autos", "repairs": 12, "revenue": 4300 }],
    "byService": [{ "service": "Full repair", "repairs": 7, "revenue": 3900 }]
  }
}

Cambiar los ajustes por API ​

Los ajustes de la Repair Station también los sirven las rutas de nay_lib, para una web o un bot. Requieren nay.settings más nay_repair.config (o nay.config):

  • GET /nay_lib/v1/settings/nay_repair lista los ajustes con sus valores;
  • PUT /nay_lib/v1/settings/nay_repair/MinPricePercent con { "value": 30 } cambia uno;
  • DELETE /nay_lib/v1/settings/nay_repair/MinPricePercent lo restablece a su valor por defecto.

Los valores se validan como en /nay. Más detalles en la página API HTTP.

Eventos de webhook ​

Elígelos en la pestaña Webhooks de /nay, consulta Webhooks.

EventoCuándoDatos
nay_repair.repairUna reparación se completa y se paga.player (nombre), identifier, station, service, price

Con un webhook de Discord, cada reparación se convierte en un embed en tu canal, en el idioma del servidor.

Extensiones ​

Otro recurso puede participar en cada reparación: cambiar precios, cerrar estaciones, reservar material. Se registra y luego exporta las funciones de abajo. Cada llamada está protegida: cuando la extensión falla, las reparaciones continúan como si no existiera. La única excepción es RepairReserve, que rechaza la reparación.

Registro ​

Llámalo desde la extensión, una vez iniciada. Devuelve false cuando el recurso no está en marcha. Solo se conserva una extensión, y se olvida cuando el recurso se detiene.

lua
exports["nay_repair"]:RegisterExtension(GetCurrentResourceName())

Funciones que exporta la extensión ​

ExportSe llamaDevuelve
RepairStatus(stationId)Antes de cada presupuesto y reparación.available (false cierra la estación), un message traducido y un header que se muestra como nombre de la estación.
RepairPrice(stationId, serviceIndex, price)En cada presupuesto y pago.El nuevo precio (entero, 0 o más), o nil para que el servicio no esté disponible.
RepairReserve(source, stationId, serviceIndex)Al empezar una reparación.true, o false y un message traducido para rechazar.
RepairRelease(stationId, serviceIndex)Cuando una reparación termina sin completarse.Nada. Devuelve la reserva.
RepairComplete(source, stationId, serviceIndex, price, account)Cuando una reparación está hecha y pagada.Nada. account es nil cuando fue gratis.

Evento ​

nay_repair:stationsChanged se dispara en el servidor y en cada cliente cada vez que cambian las estaciones. Escúchalo con AddEventHandler para refrescar tus propios datos.
